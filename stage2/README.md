# Ассемблер УВМ -- Этап 2. Машинный код

## 1. Общее описание

Учебная виртуальная машина (УВМ), вариант 22. Этап 2 добавляет к
этапу 1 формирование машинного кода: каждая команда кодируется в
80-битное слово по спецификации и записывается в двоичный файл
10 байтами, от младшего байта к старшему.

Язык реализации: Python 3, для разбора YAML -- PyYAML.
Весь код этапов 1 и 2 -- в одном файле `src/main.py`.

## 2. Спецификация УВМ (вариант 22)

Команда -- 10 байт, биты нумеруются от младшего к старшему.

| Команда | Код (A) | Поля (биты) | Смысл |
|---|---|---|---|
| Загрузка константы | 17 | B: 6--29, C: 30--50 | память[B] = C |
| Чтение из памяти | 43 | B: 6--29, C: 30--53 | память[B] = память[C] |
| Запись в память | 21 | B: 6--29, C: 30--38, D: 39--62 | память[память[D] + C] = память[B] |
| Циклический сдвиг влево | 57 | B: 6--29, C: 30--53, D: 54--77 | память[C] = память[D] цикл.сдвиг влево на память[B] |

Тесты из спецификации (проверяются в тестах и в примере `demo`):

```
load  (A=17, B=67, C=619):    0xD1, 0x10, 0x00, 0xC0, 0x9A, ...
read  (A=43, B=737, C=274):   0x6B, 0xB8, 0x00, 0x80, 0x44, ...
write (A=21, B=662, C=337,
       D=305):                0x95, 0xA5, 0x00, 0x40, 0xD4, ...
rol   (A=57, B=766, C=189,
       D=940):                0xB9, 0xBF, 0x00, 0x40, 0x2F, ...
```

## 3. Язык ассемблера (формат YAML)

Не изменился с этапа 1 (полное описание -- в `stage1/README.md`):

```yaml
- load:
    addr: 67       # B -- адрес, value -- константа (C)
    value: 619
- read:
    dst: 737       # B -- куда записать
    src: 274       # C -- откуда прочитать
- write:
    src: 662       # B -- откуда читаем значение
    offset: 337    # C -- смещение (9 бит: 0..511)
    base: 305      # D -- адрес ячейки с указателем
- rol:
    dst: 189       # C -- куда записать результат
    value: 940     # D -- первый операнд
    count: 766     # B -- второй операнд (величина сдвига)
```

## 4. Параметры запуска

```
python src/main.py <вход.yaml> <выход.bin> [--test]
```

- `вход` -- файл с программой (YAML);
- `выход` -- двоичный файл-результат;
- `--test` -- режим тестирования: машинный код каждой команды
  печатается на экран в байтовом формате, как в спецификации;
- размер двоичного файла в байтах печатается всегда.

## 5. Обработка ошибок

Все ошибки этапа 1 (файлы, синтаксис YAML, неизвестная команда,
поля: отсутствие, лишние, нечисловые, вне диапазона) -- плюс
ошибка записи двоичного файла. Код возврата: 0 -- успех, 1 -- ошибка.

## 6. Структура проекта

```

```

## 7. Запуск и тесты

Требуется Python 3.8 или новее. Зависимость устанавливается
автоматически при первом запуске скрипта (либо вручную:
`python -m pip install PyYAML`).

| Действие | Windows | Linux |
|---|---|---|
| Диалоговый запуск | `run.bat` | `sh run.sh` |
| Тесты | `run.bat test` | `sh run.sh test` |
| Пример из спецификации | `run.bat demo` | `sh run.sh demo` |
| Запуск напрямую | `python src\main.py examples\demo.yaml demo.bin --test` | `python3 src/main.py examples/demo.yaml demo.bin --test` |

Ожидаемый вывод `run.bat demo`:

```
Команд: 4. Размер файла: 40 байт. Записан: temp\demo.bin
load: 0xD1, 0x10, 0x00, 0xC0, 0x9A, 0x00, 0x00, 0x00, 0x00, 0x00
read: 0x6B, 0xB8, 0x00, 0x80, 0x44, 0x00, 0x00, 0x00, 0x00, 0x00
write: 0x95, 0xA5, 0x00, 0x40, 0xD4, 0x98, 0x00, 0x00, 0x00, 0x00
rol: 0xB9, 0xBF, 0x00, 0x40, 0x2F, 0x00, 0x00, 0xEB, 0x00, 0x00
```

## 8. Тестирование

Тесты этапа 1 (разбор языка) плюс проверки машинного кода:
каждая из четырёх команд спецификации кодируется точно в свою
тестовую последовательность байтов, программа из четырёх команд --
в склейку этих последовательностей (40 байт).

```

$ sh run.sh test
...
Ran 41 tests in 0.015s

OK
```

## 9. Соответствие требованиям к репозиторию

- README.md, .gitignore, `src/`, `tests/`, `run.sh`/`run.bat` есть;
- двоичные результаты (`*.bin`) и `temp/` исключены `.gitignore`,
  в репозитории бинарных файлов и артефактов сборки нет;
- строки кода Python не длиннее 79 символов, функции не длиннее
  40 строк, аргументов не больше 7, документация -- docstring,
  имена -- по PEP8, «магические» числа -- в именованных константах.
